# 볼륨 마운트(Volume Mount) 개념 정리

```markdown
문제 상황 복습:

컨테이너 안에서 mlflow.start_run()을 실행하면
기록(run 정보)이 컨테이너 내부의 mlruns/ 폴더에 저장됨

컨테이너는 실행이 끝나면(또는 삭제되면) 
내부에 있던 파일들도 같이 사라짐

→ 즉, 컨테이너를 껐다 켜면 지금까지 기록한 실험 결과가 
   전부 날아갈 수 있음
```

```markdown
볼륨 마운트란?

- 호스트(내 컴퓨터)의 특정 폴더와
  컨테이너 내부의 특정 폴더를 "연결"시켜주는 것

- 연결되고 나면, 컨테이너 안에서 파일을 쓰든 지우든
  실제로는 내 컴퓨터의 폴더에 그대로 반영됨

비유:
컨테이너 내부 폴더 = 창고 안의 선반
볼륨 마운트 = 그 선반을 내 방 책장과 "같은 책장"으로 만들어버리는 것
   (컨테이너가 사라져도 책장 자체는 내 방에 그대로 남음)
```

```markdown
이번 실습에 적용하면:

컨테이너 내부의 mlruns/ 폴더  
        ↕ (볼륨 마운트로 연결)  
내 컴퓨터(호스트)의 mlops-basic-practice/mlruns/ 폴더

→ 컨테이너 안에서 학습을 몇 번을 돌리든,
   기록은 전부 내 컴퓨터 폴더에 실시간으로 쌓임

→ 컨테이너를 지워도 mlruns/ 폴더는 내 컴퓨터에 그대로 남아있음
```

```markdown
볼륨 마운트가 없으면 생기는 구체적 문제 (이번 실습 기준)

1. docker run을 3번 실행해서 실험 3개를 만들었다고 가정
2. 각 docker run은 "독립된 컨테이너"를 새로 만드는 것
3. 볼륨 마운트가 없으면 매번 새 컨테이너 = 매번 새로운 빈 mlruns 폴더
4. 결과: 3번의 run이 서로 연결되지 못하고, 
   MLflow UI를 켜도 직전 1번의 run밖에 안 보이는 상황 발생

→ 그래서 이번 실습처럼 "3번 실행해서 비교"가 목적이라면
   볼륨 마운트는 선택이 아니라 필수
```

```markdown
정리: docker run 명령어에 추가되는 것

기존: docker run [이미지이름]
변경: docker run -v [호스트경로]:[컨테이너경로] [이미지이름]

-v 옵션 하나가 "이 두 폴더를 연결해라"는 뜻
```
